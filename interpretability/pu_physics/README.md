# PU 原模型的物理频带与采样时间核查

## 对象和输入

针对已有 PU 三分类模型，在六个测试轴承的原始振动 1024 点窗检查频带。模型采用原始振动窗口的幅值 FFT，不是包络谱。归因来自配套的 `ig_test.npz`：对模型原预测类别相对原次高类别的 logit 差计算积分梯度，因此它描述的可能是错误预测。各类别仅两个独立测试轴承，不能据此声称总体泛化能力。

Paderborn 原数据作者报告振动信号名义采样率 64 kHz（[原始数据论文](https://mb.uni-paderborn.de/fileadmin-mb/kat/PDF/Veroeffentlichungen/20160703_PHME16_CM_bearing.pdf)，第 7 页）；官方工况 `N15_M07_F10` 的标称转速是 [1500 rpm](https://mb.uni-paderborn.de/en/kat/research/bearing-datacenter/operating-conditions)。1024 点 FFT 在名义 64 kHz 下频点间距为 62.5 Hz。零填充或插值只加密显示，不能单独提升固有分辨能力。

为使计算可核对，使用 **NTN/SNR 6203FT150** 厂家资料作为 6203 型轴承示例：BPFO、BPFI 分别为每转 3.053、4.947 次（[产品表](https://docs.rs-online.com/a404/A700000014892791.pdf)）。**尚未证实 PU 各轴承属于该具体型号、厂牌或具有完全相同内部几何**。依此示例和 1500 rpm 分别得到约 76.325 和 123.675 Hz；最近的离散频点是 62.5 和 125 Hz。前三阶映射外圈约为 bins {1,2,4}，内圈约为 {2,4,6}，因此有两个频点重合。两组结果都是示意，不能称对真实被测轴承精确对齐。

## 时间轴一致性核查

所有 12 个测试原始文件的 `X[1]['Data']`（`Raster='HostService'`）与 `vibration_1` 数组长度相等，时间轴单调。单位字段为空；时间末值与官方 4 秒记录及文件 `Description.Measurement.Length=4` 一致，以下把它作为秒解释。每个文件的起止点、点数、间隔统计及 speed 通道均值写入 `physical_bands.json`。

`KI07` 第 2 次记录明显异常：时间轴共 274,149 点，从 0 至约 3.999997，按端点计算的平均点率约 68,537/s；274,148 个相邻间隔中有 24,989 个小于 10 微秒，最小约 4.277 微秒。其余测试文件的端点平均点率约 63,999.8–64,020.5/s。最小间隔并不等于真实硬件采样周期；这个差异可能与记录、时间戳或转换有关，原因尚不明确，不能仅凭此断言设备采样率改变或文件损坏。为避免将该记录硬套 64 kHz 映射，从频带统计中排除了该记录的 100 个窗口，剩余 1100 窗口。

假设时间轴单位为秒，将该记录按相同原始窗口起点线性插值至 64 kHz（末窗为避免越界而调整起点），不重新训练，100 窗口预测有 **9%** 改变，准确率由 **99% 变为 90%**。这是输入变换敏感性实验，不证明插值恢复了真实信号，也不能在时间轴机制未核实前用作最终校正。

## 频带归因与干预对照

对每个样本，把三个示例谐波最近频点的绝对归因相加，再除以该样本全部 513 个频点的绝对归因之和；六个轴承的样本平均值为外圈示例 0.585%–0.754%，内圈示例 0.473%–0.676%。这只是特定频点对原预测与次高分数差的归因占比，不是物理故障频率能量占比；轴承、预测对和频谱环境不同，不应把均值解释为独立验证或物理规律。

在这 1100 个窗口中，将 62.5 Hz 单个频点的标准化特征替换成训练均值，**5/1100** 个原预测改变；将 125 Hz 单个频点同样替换，**0/1100** 个原预测改变。这是特征空间置值，可能生成偏离真实信号分布的输入；频点之间也可能互补。它不证明该频段是否参与真实故障，也不能排除高频共振携带了故障冲击的调制信息。[MathWorks 的轴承诊断示例](https://www.mathworks.com/help/predmaint/ug/Rolling-Element-Bearing-Fault-Diagnosis.html)说明了利用包络谱检查冲击调制频率的方法；当前模型并未使用包络谱。

## 复算

脚本依赖预先生成的 IG 数据 `ig_test.npz`（包含模型特征及归因），默认为相邻的 `interpretability/pu/ig_test.npz`。项目根目录执行：

```powershell
$env:PYTHONNOUSERSITE = '1'
.\.venv\Scripts\python.exe .\interpretability\pu_physics\analyze_physical_bands.py
```

也可以用 `--ig` 指定配套 IG 数据路径。脚本将覆盖本目录的 `physical_bands.json`。若脚本尚未安装到项目布局下，可设置 `BEARING_PROJECT_ROOT` 指向项目根目录。此脚本不重新训练、不修改输入数据。
