# XJTU-SY 按轴承留一：分钟级剩余寿命比较

这是一组在已有论文复现基础上新增的研究基线，不是原文实验的精确复刻。15 个轴承、3 种工况分别进行完整轴承留一测试；每折从其余轴承中按工况各留出 1 个验证轴承，其余 11 个轴承训练。所有随机训练种子使用同一套固定划分。详情见 `results_merged/folds.json`。

## 标签与数据

每次原始采集两通道各 32,768 点，采样率为 25.6 kHz，相邻采集按 1 分钟处理；数据的每条记录实际只包含约 1.28 秒波形，不能把最近 10 条记录当作连续 10 分钟振动数据。第 `i` 条记录，以第 1 条的时间为零，已运行时间设为 `i−1` 分钟；共 `N` 条记录时，目标设为 `N−i` 分钟，即距最后一次采集的时间。例如 123 条记录的第一条目标为 122 分钟。某些来源将 123 次采集称为 123 分钟的采集次数口径，两者口径不同。

**最后采集时刻仅是可观察的试验终点代理，不是精确测得的轴承机械失效时刻。** `N` 和 `N−i` 只能用于监督标签与离线评价，不能作为推理输入。评估中最后 20% 阶段按测试轴承已知终点划分，仅用于事后统计，不能作为上线时的阶段信息。

当前输入来自**当次记录本身**：水平/垂直通道的 RMS、峰值、方差、超额峭度、偏度，加上已运行分钟数、标称转速和载荷。没有用同一轴承未来记录、总寿命、未来终点或测试轴承的整轨迹统计来构造输入。`data/features_and_labels.csv` 保留逐记录特征、标签和相对源路径；`data/manifest.json` 保留每个轴承的数量及工况。

## 模型与选模

四种模型使用相同外层留一轴承与内层验证分组，训练、验证、测试轴承互不重叠：

- `age_ridge`：以当前已运行分钟、转速和载荷为输入的 Ridge 基线。
- `features_ridge`：同样的时间与工况，加上全部振动特征的 Ridge。
- `mlp`：相同完整输入的单隐藏层 MLP，候选宽度 64、128。
- `kan`：相同完整输入的小型双层自适应 Chebyshev KAN，候选隐藏宽度 8、16、阶数 3。使用论文附录的多项式门控层；没有显式稀疏正则，不应称为稀疏 B 样条 KAN。

各 Ridge 比较两个 alpha；MLP 和 KAN 比较两个宽度。两个神经网络采用同样的优化器设置、训练轮数上限与早停规则；参数规模大致相当，但不同结构的实际计算预算并非完全一致。所有候选使用验证轴承的**宏平均 MAE**选择，测试轴承从不参与缩放、训练、早停或选型。训练样本和标准化按轴承等权，以减少长寿命轨迹的主导。模型在验证选型后保留对应训练权重，不将验证轴承再并入训练。

验证和测试时，四种模型的负预测统一截断为 0 分钟。神经网络的目标值标准化仅由训练轴承按轴承等权拟合；实际训练损失是均方误差，最终选型指标是验证宏 MAE。

完整实验对每个测试轴承使用训练种子 42、43、44；随机种子不构成额外独立轴承。默认最大 60 轮、8 轮早停。结果按轴承先求 MAE 或 RMSE 再平均，最后对训练种子求平均；这里的宏 RMSE 是每轴承 RMSE 的算术平均，不是把所有采集记录混在一起再计算的总体 RMSE。还报告平均高估分钟数、高估比例和事后最后 20% 阶段指标。

这是一种已见工况内的跨轴承检验：每次训练都含三种工况，不能称为未见工况泛化。只设一组固定验证轴承，未给出独立轴承水平的可靠置信区间；数据量有限，个体、试验台和工况结论都应谨慎外推。

## 真实运行结果

以下为 15 个测试轴承及三个训练种子的平均；完整逐轴承、逐工况和逐种子数值保存在 JSON：

| 模型 | 轴承宏 MAE（分钟） | 轴承宏 RMSE（分钟） | 后期平均高估（分钟） |
| --- | ---: | ---: | ---: |
| 年龄与工况 Ridge | 304.38 | 343.04 | 302.26 |
| 振动特征 Ridge | 333.42 | 397.85 | 286.39 |
| MLP | 305.58 | 366.58 | 230.78 |
| Chebyshev KAN | 287.31 | 347.63 | 157.05 |

后期为每条测试轨迹的最后 20%（按离线终点确定），高估为 `max(预测−标签, 0)` 后逐轴承平均。尽管 KAN 本次宏平均 MAE 最低，它按三个种子平均只在 **6/15 个轴承**上优于 MLP；因此不能据此宣称普遍优越或统计显著。KAN 最后阶段的平均高估仍有约 157 分钟，不足以直接支持维护部署。不同工况及轴承误差差异很大：KAN 的三个工况平均 MAE 约为 108.74、154.20、598.98 分钟。模型没有测试从未见过的工况。

## 运行

从项目根目录使用本项目已建的 Python 环境：

```powershell
$env:PYTHONNOUSERSITE = '1'
.\.venv\Scripts\python.exe .\rul_study\build_features.py --data .\data\XJTU-SY\XJTU-SY_Bearing_Datasets
.\.venv\Scripts\python.exe .\rul_study\run_experiments.py --seeds 42,43,44 --epochs 60 --patience 8 --output .\rul_study\results
```

`build_features.py` 检查各轴承预期文件数、连续编号、CSV 列名、采样点数和有限值。为节省重复处理时间，`data/cache/*.npz` 按轴承缓存特征，当前只检查缓存形状，不识别相同文件数下的原始内容变更。**如果更换原始数据版本或修改 CSV，请先清除 `rul_study/data/cache` 并重新构建**；请保留原始档案的来源和校验记录。首次处理会扫描全部原始 CSV，耗时较长。

参考项目原有 `.venv` 基于本机 Anaconda 和 CPU PyTorch；移动项目或更换依赖版本时需重新创建环境。`run_experiments.py --help` 可查看参数。已有结果存放在 `results_merged`；重跑会覆盖指定输出目录中的结果。

## 输出与复核

- `results_merged/summary.json`：总体、各工况、各测试轴承和各训练种子指标。
- `results_merged/folds.json`：每折训练/验证/测试轴承、候选超参、早停记录和测试指标。
- `results_merged/predictions.csv`：逐采集记录、逐种子、逐模型预测及事后阶段标记。
- `results_merged/checkpoints/`：每个测试轴承和随机种子的模型、训练集缩放参数、模型参数和分组。
- `merge_seeds.py`：三个独立种子进程完成后检查各自 15 折、每种子 9,216 条预测、固定划分及检查点，再合并结果。

数据源：[XJTU-SY 原始发布方](https://github.com/WangBiaoXJTU/xjtu-sy-bearing-datasets)。原始多卷档案来源与 SHA-256 见项目 `data/XJTU-SY/sha256.csv` 和 `mirror_metadata.csv`；本研究的文件与标签清单另见 `data/manifest.json`。
